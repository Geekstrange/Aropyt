# Aropyt v0.2.4 — Two Translation Gaps

One fix, in two places.

## What was wrong

`formatting.ts` declares six heading commands, each carrying a Chinese title:

```
{ id: 'aropyt.h4', title: '四级标题', ... }
```

Those titles get translated at render time through a lookup table. The table
only knew the first three levels, and the eight locale files only carried
`toolbar.h1` through `toolbar.h3`. Scrolling the heading wheel past level 3
therefore left the tooltip on the raw Chinese string — `四级标题` — with the
interface in English.

The second gap was the hint itself:

```
title={`${title}（滚轮切换级别）`}
```

A template literal. No locale could change it.

## The fix

- `toolbar.h4`–`h6` and `toolbar.headingWheel` added to all eight locale files
- the three missing entries in the title lookup
- `WheelButton` reads the suffix through `useT()`

That last point matters. The module-level `t` returns the right string, but it
is not a hook — switching language would leave the tooltip showing the previous
one until something else re-rendered the button.

## A detail worth keeping

The English value carries a leading space:

```
zh: '（滚轮切换级别）'
en: ' (scroll to change level)'
```

The space belongs in the translation, not in the template. Chinese uses a
full-width bracket that already carries visual spacing; a half-width space
before it would look wrong. English has no such bracket, so it needs one.

## Verifying

Hover the heading button and scroll through all six levels. With the interface
in English, every tooltip should read:

```
Heading 1 (scroll to change level)
Heading 4 (scroll to change level)
Heading 6 (scroll to change level)
```

Before this release, levels 4 through 6 printed their Chinese titles inside an
English interface.
