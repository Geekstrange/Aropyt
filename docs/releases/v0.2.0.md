# Aropyt v0.2.0 — Take It With You

Sync arrives, and with it a lesson about what "sync" is allowed to do. Your
notes follow you between machines through a WebDAV server you already have —
Nextcloud, Synology, Jianguoyun, anything that speaks RFC 4918. It is off
until you turn it on.

## Sync, and two ways it was wrong

The first version of this shipped with a decision that looks reasonable in a
table and is indefensible in practice: if a file existed locally, existed in
the last-synced snapshot, and was missing from the server, it was deleted
locally. The reasoning was "the user must have removed it on the other
machine."

Over WebDAV that reasoning has four answers that look identical: the drive was
emptied, the address points somewhere else, the account changed, or the
provider's trash hid the files. In every one of them the local copy is the only
copy, and deleting a file on Windows with the file-system API does not put it
in the recycle bin.

So sync no longer deletes anything locally. A file present here and absent
there is kept, recorded once, and left for you to decide. Deletion only
travels one way — local to remote — because that is the only direction where
an explicit human action happened.

The second mistake was more embarrassing: two machines sending the same
project to two different folders. The folder name carried a hash of the
workspace's *absolute path*, so `test` became `test-9wxtej` on one machine and
`test-1uskj7` on the other. Every run reported success, every file uploaded
cleanly, and nothing ever converged. The hash is gone.

**Sync is beta and starts disabled.** Turn it on in Settings → Sync, fill in
the address and account, press Test connection. The password goes to the
system keychain, not to a settings file.

## Images travel with the text

`![](assets/a.png)` used to arrive on the second machine as a broken image
with no error anywhere — only the seven text extensions were synced.

Files now move as bytes rather than strings, so one path serves both. Text is
just its UTF-8 bytes. A PNG pushed through a string is corrupted by UTF-8
decoding, and the decode reports success, which is why the damage only showed
up later as a missing image.

reach the server as mojibake — `Aropyt额外权益草案.md` landed as
`Aropytå¥é¤ææçèæ¡.md` — because the path was appended to the URL verbatim and
read back as ISO-8859-1. And each file write was sending its own MKCOL, so a
13-file upload produced twelve redundant 405 responses.

## Sync no longer downloads everything to decide nothing changed

WebDAV's PROPFIND carries size and modification time, which was being ignored:
every run pulled every file down just to hash it. Steady state is now one
PROPFIND and zero downloads, and files whose metadata matches the snapshot
reuse the stored hash.

That also fixes something you could see: the direction arrow never had time to
appear, because the download-and-hash phase was where all the time went.

Sync runs on its own after a save (3 s, debounced) and after startup (5 s),
and a trigger arriving mid-run queues exactly one more instead of being
dropped. Successful runs are silent — an occasional "sync finished" banner
turns the normal state into noise. Failures and conflicts still speak up.

When a conflict does happen, the server's version is recorded as a history
entry marked **Remote** instead of being written beside your file as
`note.conflict-20261101T081500.md`. That copy used to show up in the file
tree and get uploaded again on the next run, so every conflict bred another
one.

## PDF export, in two steps, and then a third

The Store build could not export PDF at all. Three separate causes stacked up:

1. `--pdf-engine=typst` makes pandoc start typst, and that grandchild process
   is blocked inside an MSIX / AppContainer package.
2. The new two-step path never ran: the `compile` subcommand was missing, so
   typst read the `.typ` path as a subcommand name.
3. typst has no network permission in that sandbox either, so a document
   containing `https://…` failed to load it as a local file.

All three are fixed. Remote images are downloaded into the workspace before
typst sees them — the app has network access, typst does not — and an image
that cannot be fetched is dropped along with its markup, because one dead link
should not take down the export.

**This still has not been verified in a packaged build.** There is no
packaging environment here. If the Store build fails again, the sandbox blocks
even app-initiated launches, and the fallback is HTML export plus browser
printing.

## Search across the whole workspace

`Ctrl+Alt+F` searches every text file and jumps to the matching line. It walks
the tree once in Rust — walking from the front end means one IPC call per
file, each serialising the whole document.

The search panel also gained a match count. Its "Select all" button is gone:
that button only walks the *current selection*, so with a cursor it matched at
most one place, and selecting hundreds of disjoint ranges is not a workflow
this editor has.

## Saving a new document stops rearranging your projects

Save-as used to register the target folder as a workspace, because the
workspace API only accepts paths relative to a root. Every first save
therefore added an entry to your project list — and, worse, put everything in
that folder within sync's reach.

It now writes the absolute path directly. The file behaves like any other
externally opened one: it does not appear in the file tree, because it is not
part of any workspace.

## Upgrading

Nothing to migrate. Two things to know:

- **Sync is off.** Settings → Sync → turn it on, fill in the address, press
  Test connection. If you have been testing sync with an earlier build, delete
  the old `<name>-<hash>` folders on the server; only `<name>` is used now.
- **The first sync after upgrading uploads everything once.** The hashing
  changed from UTF-16 code units to bytes so that images and text share a
  path, which means old snapshots no longer match. Nothing is deleted.
