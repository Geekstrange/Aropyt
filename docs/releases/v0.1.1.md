# Aropyt v0.1.1 — 面板快捷键、vim 全键盘与调试面板

这一版集中在**操作效率**与**可观测性**：把散落在各处的面板收进统一的快捷键，把 vim 模式补成真正的全键盘操作，并把"用户遇到问题时能提供什么"变成面板里的一键操作。

## 面板快捷键

六个入口，全部是 toggle —— 再按一次关闭。

| 快捷键 | 面板 |
| --- | --- |
`Ctrl/Cmd+Shift+X` | 插件面板 |
`Ctrl/Cmd+Shift+G` | 编辑历史 |
`Ctrl/Cmd+Shift+,` | 设置 |
`Ctrl/Cmd+Shift+M` | vim 模式开关 |
`Ctrl/Cmd+Shift+E` | 聚焦编辑区 |
`Ctrl/Cmd+Shift+P` | 命令面板 |

按键判断用 `event.code`（物理键位），不受 Shift 与键盘布局影响 —— `Shift+,` 的 `event.key` 是 `<` 而非 `,`，用 key 判断永远匹配不上。

## vim 模式：全键盘

编辑器内本来就是全键盘（hjkl、dd/cc/yy、cw、块选、`.` 重复），这一版补齐**离开编辑器之后**的链路。

- **ex 命令**：`:w` 保存、`:q` 关闭当前标签（有未保存修改时走确认）、`:wq` 保存并关闭
- **`Ctrl+F`** 打开编辑区查找（`Ctrl+G` / `Shift+Ctrl+G` 不做绑定）
- 状态栏保留 `-- NORMAL --` / `-- INSERT --` 子模式指示

## 字数、行数、词数统计

状态栏右下角显示 `行 · 词 · 字`：

- 中文按 CJK 区间计"字"
- 英文按连续字母数字计"词"
- 口径与 Word 的中文字数统计接近，混排文档里三个数字都有意义

数字用等宽排版（`tabular-nums`），输入时不跳动。

## DEBUG 模式

`F12` 打开，底部停靠 —— 不遮挡编辑区，能一边操作一边观察。

**指标**：FPS、输入延迟、堆内存、主线程阻塞次数、版本。

**输入延迟**指按键到下一帧渲染的实际间隔（EMA 平滑）；**主线程阻塞**指长任务（>50ms）的次数与占比 —— 这两项只在调试面板里出现，不占状态栏。

**日志**：拦截 `console.*`、未捕获异常、未处理的 Promise 拒绝，环形缓冲 500 条，**应用启动即开始收集**（不是打开面板才开始）。支持文本搜索与级别过滤。

**复制诊断报告**：一键生成含版本、平台、设置快照、当前文档状态、性能指标与最近 200 条日志的 Markdown —— 直接粘进 issue。

## 修复

- **`Ctrl+Shift+B` 只能关不能开**：handler 只注册一次却读渲染期闭包里的旧值，每次都朝同一方向取反。改为读实时状态；打开后焦点自动进入文件树。
- **`Ctrl+Shift+,` 完全无效**：`Shift+,` 的 `event.key` 是 `<`，改用 `event.code`。
- **调试面板日志为空**：日志拦截原来在面板打开时才安装，启动与插件加载的日志全部丢失。
- **调试面板只露出一条边**：`.app` 是 3 行 grid，第 4 个子元素落进高度为 0 的隐式行。
- **`Ctrl+F` 查找丢失**：搜索面板的 `search()` 扩展一直装着，但 keymap 里没有 `Mod-f` 条目。已显式绑定 `openSearchPanel`。

## 已知限制

- vim 的 `:q` 关闭的是当前标签，不是整个应用（与标签模型一致）
- 调试面板的堆内存依赖 `performance.memory`（WebView2 可能显示 —）
- 主线程阻塞与输入延迟仅存在于调试面板，状态栏不再显示
