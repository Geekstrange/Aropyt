# Aropyt v0.1.5 — Workspace, Cleaned Up

Two additions to the workspace itself, plus two long-standing file-tree bugs
that were hiding behind them.

## Added

**Remove a folder from the workspace.** Directory rows in the file tree now
carry a `×`. Point at a row and it appears; on a touch screen it is always
visible, because there is no hover there. Removing hides that folder **and
everything under it** — the tree stops recursing at the removed node, so a
single click clears a whole subtree.

Nothing on disk is touched. This is a view setting, not a delete, and it is
remembered per workspace name, so a `node_modules` you never want to see stays
hidden after a restart. `恢复已移除的目录` in the command palette brings
everything back — without that, removing would be a one-way street.

**Close workspace.** The tree gained a header row showing the workspace name
with a close button; the command palette has `关闭工作区` as well. Closing
clears the remembered workspace, so a folder you deliberately closed does not
reopen on the next launch. Open tabs are closed with it — their relative paths
have no meaning once the workspace is gone — and if any tab has unsaved
changes, you are asked first.

## Fixed

**File-tree keyboard navigation fired twice.** The `keydown` handler and the
focused-row state had been pasted *inside* the directory row's click handler.
Every click on a folder registered one more listener, so a single `j` could
skip several rows, and the keyboard cursor reset to the top on every click.
Both are back at the mount scope, where they belong; the leftover debug
`console.log` calls are gone too.

**Collapsing a folder could empty the tree after restart.** The collapsed set
was stored as `null` to mean "nothing collapsed", but `Memento.get` decides
with `has(key)`, so it handed back `null` instead of the fallback, and
`new Set(null)` throws. Anyone who had ever collapsed a folder would find an
empty file tree on the next launch, with nothing in the console to explain it.
The key is now deleted instead of set to `null`, and the read is defensive.

## Note for packagers

**The MSI target is gone.** Nobody installed it: the Windows download has
always been `*_x64-setup.exe` (NSIS), so building the MSI only meant running
WiX on every tag for nothing. Release assets for Windows are now just
`*_x64-setup.exe` and `*_arm64-setup.exe`.

**A Microsoft Store package is attached.** `Aropyt_0.1.5.0_x64_arm64.msixupload`
is built in a separate job from the same binaries and uploaded to the release.
It is a submission artifact, not an installer — double-clicking it does
nothing useful, because it is unsigned by design. Microsoft re-signs it after
certification. Install `*_setup.exe` unless you are submitting to Partner
Center; see `src-tauri/msix/README.md`.

## Known limitations

Unchanged from v0.1.4.
