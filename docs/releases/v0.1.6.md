# Aropyt v0.1.6 — LaTeX, Screenplays, and Two Projects at Once

Three new capabilities this time, plus a pass over the rendering layer that
had been running without styles since the beginning.

## LaTeX

Opening a `.tex` file now gives you a **structure view** in the sidebar —
`\part`, `\chapter`, `\section`, `\subsection` and so on, indented by level,
click to jump — and **real typesetting in the editor**.

Math is rendered in place with KaTeX: inline `$…$` and `\(…\)`, display
`\[…\]` and `$$…$$`, and the `equation` / `align` / `gather` / `multline`
environments with their numbering. The cursor expands a formula back to
source; leaving it re-typesets.

The rest of the document is laid out too. Title page (`\title`, `\author`,
`\date`, with `\today` resolved), abstract, quotes, `verbatim` /
`lstlisting` blocks, `\newpage` rules, and **tables** — `tabular` with `&`
and `\\`, `\toprule` / `\midrule` / `\bottomrule`, `\caption`, and `l/c/r`
column alignment.

Inline commands that only affect layout are applied instead of shown:
`\textbf` / `\emph` / `\texttt` / `\underline`, `\LaTeX` / `\TeX`,
`\ref` / `\cite` (the key stays visible, dimmed), `~` becomes a space,
escaped characters come back. Commands with no output — `\label`,
`\maketitle`, `\tableofcontents`, `\begin{document}` — disappear.

The file on disk stays plain LaTeX.

## Fountain

`.fountain` files get a **scene list** in the sidebar (scene headings and
sections, with line numbers) and line-level screenplay styling: scene
headings bold, character names centred, dialogue indented, parentheticals
and transitions right-aligned.

Title pages, notes `[[ … ]]`, boneyard blocks, lyrics and page breaks are
recognised as well, and an `INT. …` inside a boneyard is no longer mistaken
for a scene. The plugin only adds classes to lines — not a single character
is rewritten, so editing, undo and save all take the native path.

## Multiple workspaces

Opening a second folder no longer replaces the first. Workspaces coexist:

- a **workspace bar** at the top of the sidebar lists every open project
  (coloured dot + name); click to switch, and the file tree, the save route
  and `context.workspace` all follow
- every tab carries a thin colour bar at its top edge keyed to its own
  workspace, so two `notes.md` from two projects are distinguishable in one
  tab strip
- drafts and edit history are stored per workspace; drafts saved under the
  old flat key are migrated on read
- the list is persisted as `workspace.roots: string[]` alongside
  `workspace.active`, and restored one by one on launch

On the native side the workspace went from a single root to a registry:
`set_workspace` returns `{ id, name, root }` and file commands carry a
`rootId`, so interleaved async calls can never land on the wrong root.

## Rendering

**Block HTML finally has styles.** The HTML markdown-it produces inside the
editor had no rules at all — lists used the browser's 40px indent, quotes
were just an indented paragraph, code blocks had no border and no
background. They now follow the demo page: list spacing, a 3px quote rule
with muted text, table borders and header tint, and code blocks as rounded
cards with inline code kept visually separate.

**A list item no longer takes two lines.** `.cm-md-block` sits inside the
editor's `white-space: pre-wrap` content layer and inherited it, so the
newlines between `</li>` and `<li>` became real line breaks: list gaps were
41px instead of 23px, and nested quote rules ran one line past the text.

**Reference-style images work.** `![logo][img-ref]` rendered as plain text
because each block is rendered separately, while `[img-ref]: https://…`
lives in another block — `env.references` was empty at render time. The
document's reference definitions are now collected once and shared by every
block.

**Task checkboxes are clickable.** They used to be `<input disabled>` —
grey, unclickable, and the only way to tick one was to edit the source by
hand. They are drawn with `appearance: none` now (brand-green outline,
filled with a white check when done), and clicking rewrites the `[ ]` /
`[x]` in place. The duplicate bullet in front of the checkbox is gone, and
the toolbar's task-list button works on empty lines and toggles off again.

## Reliability

**A plugin could activate twice** when two activation events arrived in the
same tick (`onLanguage` + `onView` when opening a `.tex`): the view was
registered twice and the editor extension injected twice. Activation is now
de-duplicated per plugin; concurrent callers share one promise.

**The sidebar could sit on “Activating plugins…” forever.** `onView` was
dispatched through a `Set` that survived remounts (HMR, collapsing and
expanding a view, a view hiding and reappearing by language), so if the
first attempt failed it never fired again. Dispatching is idempotent now,
and after three seconds a view says “Plugin is not activated.” with a retry
button instead of spinning.

**The DEBUG panel was fighting itself.** Its log list used a colliding React
key (source + time + first 40 characters of the text), which made the panel
report duplicate keys on every frame — 122 of those warnings were enough to
flush the log buffer and lose the context you opened it for. Entries now
carry a session-unique id, and `%s` / `%d` / `%o` placeholders in console
arguments are formatted instead of left raw.

## Smaller fixes

- The status bar no longer repeats the current file's language — the tab
  badge already says it.
- The header no longer shows the workspace name; workspace identity moved to
  the tab colour bar and the new sidebar bar.
- Opening a file from the file tree now works for every registered language,
  not just Markdown.
- `align` / `gather` blocks render: the environment shell used to be
  stripped before handing the body to KaTeX, whose alignment tab is only
  valid inside the environment.
- Removing a folder from the tree, closing a workspace, and crash recovery
  all still behave as before; the regression scripts were updated for the
  new workspace contract.

## Theme

The dark green `#0d7259` used for links, H2 and syntax strings is replaced
by `#4aa63d`, matching the brand green already used by toolbar accents. The
website and the demo page follow.
