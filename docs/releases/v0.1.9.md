# Aropyt v0.1.9 — Take It With You

This release adds sync: your notes follow you to another machine through a
WebDAV server you own. It also carries five fixes, four of which only appear
in the Store build.

## Sync, with a server you choose

Aropyt does not provide storage and never asks for an account. Point it at a
WebDAV endpoint — Jianguoyun, Nextcloud, Synology, anything that speaks
RFC 4918 — and it treats that folder as the other copy of your workspace.

**It is off until you turn it on.** Settings → Sync has a switch, and until
that switch is on nothing leaves your machine; filling in an address alone
does not start syncing. That default is deliberate: this layer has only ever
talked to a local test server. TLS quirks, each provider's tolerance for
`PROPFIND`, and non-ASCII path encoding all need a real server to prove out,
which is why the feature ships marked beta.

Three design choices worth knowing:

- **Conflicts produce two files, never one winner.** If both sides changed,
  the remote copy is written beside yours as
  `note.conflict-20261101T081500.md` and the original is left alone. Every
  "remote wins" policy can erase hours of writing on the other machine, and
  the user never sees it happen.
- **The password lives in the system keychain.** Not in `settings.jsonc`,
  which is plain text and ends up in screenshots and dotfiles repositories.
- **Only text files travel**: `md`, `markdown`, `txt`, `tex`, `latex`, `ltx`,
  `fountain`. Images would need base64 transport plus a size-first
  comparison, which is a different cost model from "one character changed".

Sync runs on its own once enabled — three seconds after a save, five seconds
after startup — and is silent when it succeeds. Two runs never overlap; a
trigger arriving mid-run queues exactly one more. The status bar's dot turns
blue while bytes are moving, and the toolbar icon follows the direction:
`syncUp` while uploading, `syncDown` while downloading, plain `sync` when
done.

## PDF export, in two steps

The Store build failed to export PDF while the development build succeeded,
with the same document and the same typst. The cause is the sandbox: the old
path passed `--pdf-engine=typst`, which makes **pandoc** start **typst**, and
that grandchild process is blocked inside an MSIX / AppContainer package. It
fails identically no matter which typst path is configured, because the
attempt never happens.

PDF now runs in two steps: pandoc converts to typst source with no engine
involved, then Aropyt itself compiles it. Starting typst from the app is the
same privilege level as starting pandoc, which does work.

An end-to-end test that invokes the real pandoc and typst found that this new
path never worked at all — the `compile` subcommand was missing, so typst
read the `.typ` path as a subcommand name. That one had nothing to do with
the sandbox and would have broken PDF everywhere, development builds
included.

**This fix has not been verified in the Store build.** There is no packaging
environment here. If the Store build still fails, the sandbox blocks even
app-initiated launches, and the fallback is HTML export plus browser
printing — deferred to v0.2.0.

## The rest

- **Export failures say why.** stderr and stdout are now drained while the
  child is still alive; they used to be read after exit, which returns empty
  under MSIX, so "missing engine", "path blocked" and "font not found" all
  looked like `pandoc exit code Some(1)`. Messages carry the exit code,
  stderr, stdout, and the executable path.
- **No more console windows at startup.** Release builds have no console, so
  Windows gave every console child a fresh black window: two appeared before
  the UI (pandoc and typst are probed in parallel) and a third during export.
  All four spawn sites set `CREATE_NO_WINDOW` now.
- **Closing a separately opened file left its content behind.** `closeTab`
  decided "is this the active tab" with its own strict comparison, which is
  never true for a file outside the workspace — it took the "not active"
  branch, removed the tab and returned, leaving the editor untouched.
- **Opening a file outside the workspace logged an error.** `openFile` handed
  the absolute path to the workspace API, whose contract is a path relative
  to the workspace root. Such paths now route to the external-file reader.

## Upgrading

Nothing to migrate. Two notes:

- **Sync is off by default.** Enter the server address, user name and password
  in Settings → Sync, press **Test connection** first (it reports the HTTP
  status in place), then turn on automatic sync.
- **PDF still needs typst installed.** Nothing is bundled, by design — the
  app only probes for pandoc and typst and remembers the paths you give it.
