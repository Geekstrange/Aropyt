# Aropyt v0.1.7 — Edit Where You Read

This release is mostly about the editing surface itself: code blocks and
diagrams become editable in place, a long-standing IME crash is gone, and
the rendered blocks finally look like what the demo page promised.

## Code blocks and diagrams edit in place

Clicking a fenced code block used to throw the whole block back to source —
to change one line you had to stare at a screenful of backticks and the
fence info string, then click away to fold it up again.

Now the block itself turns into an editor. The surrounding document does not
move, the fence and language tag are preserved, and the caret lands at the
**end** of the text rather than selecting everything (selecting everything
means "click once, type one character, lose the whole block").

- **Blur commits.** Click away and the change is kept — no confirm/cancel row
  to scan past every time. `Esc` discards, `Ctrl/Cmd+Enter` also commits,
  `Tab` inserts two spaces.
- Unchanged content produces **no undo step**; an empty dispatch would
  otherwise litter the history with no-ops.
- The same editor works for **mermaid** blocks. Clicking a diagram opens its
  source, and the edit box is taller (nine rows) and full-width.

**mermaid editing has live preview.** A preview pane sits under the editor
and re-renders as you type (260 ms debounce). Rendering is serialised — the
mermaid API holds global state and concurrent calls stomp on each other —
and stale results are dropped by ticket number, so fast typing can't get
overwritten by a slower earlier render. Syntax errors print mermaid's own
message in the preview pane instead of leaving a blank box.

## A quieter, more controllable interface

- **The toolbar can be hidden** with `Ctrl/Cmd+Shift+H` or the
  "Show toolbar" switch in settings. The editor moves up to the tab bar
  (+35 px, no gap) and the state is stored in `settings.toolbar.open`, so it
  survives a restart. Two ways back: the shortcut and the settings switch —
  the toolbar's own buttons are gone by definition.
- **`Ctrl/Cmd+Shift+O` opens a workspace** (folder picker). It runs the same
  command as the toolbar button, through the same error reporting, so a
  failed pick tells you why instead of doing nothing.
- **Quote and alert colours are now tokens of their own.** `--quote-border`,
  `--alert-note`, `--alert-tip`, `--alert-important`, `--alert-warning`,
  `--alert-caution`, plus `--quote-width` / `--alert-width`, identical in
  both themes. They used to borrow `--md-h1` / `--md-link` / `--md-h3` /
  `--md-h5` / `--md-danger` / `--md-accent` — document semantics used in 60+
  places, so adjusting an alert border repainted headings and links too.

## GitHub-style alerts, actually

The alert blocks were "GitHub flavoured": a tinted background over the whole
block, a border in the generic quote colour instead of the type colour, and
body text dimmed by the quote rule.

Three causes stacked up. `.markdown-alert` declared its own `background`;
CM6's base theme compiled `.ͼ1 .cm-md-block blockquote` at specificity
(0,2,1), which outranked `.cm-md-block .markdown-alert` (0,2,0) and replaced
the type colour with `--md-border-strong`; and the same properties were
declared in two places, so which one won depended on generation order.

The base theme's blockquote declarations are gone (styles live in
`styles.css` only), the background is removed, and the border and title now
take the type colour — Note blue, Tip green, Important purple, Warning
amber, Caution red — with body text at normal contrast.

## Markdown that matches what you typed

- **Line breaks inside a paragraph now render.** markdown-it defaults to
  `breaks: false`, where only two trailing spaces or a backslash count.
  The sample document `test/basic.md` contains a line that literally reads
  "this line ends with two spaces and should render as a soft break" — and
  on disk it ends with `。`, zero spaces. Trailing whitespace does not
  survive save, `git commit` or copy-paste. `breaks: true` makes a single
  newline a `<br>`, matching GitHub issue bodies; list continuations get the
  same treatment.
- **LaTeX blocks no longer shift the caret a line down.** Block widgets
  expressed spacing with `margin`, but CM6 measures widget height with
  `offsetHeight`, which excludes margins — the real layout was taller than
  the height map, so every subsequent click landed one line low. Spacing is
  padding now, and KaTeX calls `view.requestMeasure()` after it fills in the
  typeset result.
- **Hand-written HTML controls work.** `<input type="checkbox">`,
  `<details>`, buttons — CM6 calls `preventDefault()` on widget mousedown to
  place the caret, which killed every default behaviour. `ignoreEvent` now
  exempts control types rather than one class name. `<a>` is deliberately
  excluded: clicking a link navigates the WebView in the desktop shell.
  `<kbd>`, `<summary>` and hand-written checkboxes also got styling.

## Workspace and tabs

- **Opening a single file no longer registers its folder as a workspace.**
  It opens as an external file (`workspaceId: null`, no workspace colour bar
  on the tab), and saving goes through `write_external_file` back to the
  original path. Use "Open folder" when you actually want a project.
- **External files can be closed with ×.** The close button dropped the
  `workspaceId`, and `closeTab` fell back to "current workspace" — an
  external file's owner is `null`, so it never matched; only middle-click
  worked. `activateTab` / `closeTab` / `findTab` now take `workspaceId` as a
  **required** parameter, so the compiler catches every omitted call.
- Those tabs also stopped being highlighted, because the render layer
  recomputed `path + workspaceId` on its own — now it asks
  `runtime.isTabActive()`.
- External file saves used to produce **no feedback at all** (the branch only
  handled errors), and since "open file" now always takes that path, every
  `Ctrl+S` looked like a no-op.

## Editing reliability

- **Typing Chinese no longer freezes the editor.** The first error in the
  report was `RangeError: Decorations that replace line breaks may not be
  specified via plugins`. Upstream of it: `if (update.view.composing) return`
  in the view plugin — during IME composition the document changes while the
  decorations stay frozen in the old coordinate space. CM6 cut tiles with
  those ranges, hit an out-of-range position or a replaced line break, and
  its tile index was corrupted; every later measure and click then threw
  `TilePointer.advance` / `No tile at position <n>` and the editor stopped
  responding. Decorations are now mapped to the new coordinates as soon as
  the document changes (position only, no DOM churn — composition is not
  interrupted), illegal items are dropped with a warning, and a full rebuild
  happens when composition ends. Reproduced and regression-tested with CDP's
  `Input.imeSetComposition`.
- **Task items no longer render as "☐ ] text".** The replacement range came
  from the lezer `TaskMarker` node, whose end sometimes sat before the `]`,
  leaving a stray bracket. Position is now derived from the line text: a `[`
  within one character of the node start, followed by exactly one character
  and `]`. If the shape doesn't match, the line stays as source — a
  half-replaced checkbox is harder to explain than no checkbox.

## Website

The Microsoft Store badge in the hero was a static image from
`get.microsoft.com/images/<locale>%20<variant>.svg`, a CDN that only ships a
handful of locales — `ja`, `ru` and `de` returned 404 and the slot was
simply empty. It now uses the official `ms-store-badge` web component (all
nine languages, official artwork). `theme` follows the **site** theme rather
than the component's `auto` (which reads the OS preference), the element is
rebuilt on language and theme changes, and a plain-text fallback link
appears if the script hasn't registered within six seconds.

## Upgrading

No configuration migration needed. `settings.toolbar.open` is new and
defaults to `true`; older `settings.jsonc` files read fine. The renderer now
treats a single newline inside a paragraph as a hard break — if you have
documents that relied on soft wrapping for layout, separate those lines with
a blank line instead.
