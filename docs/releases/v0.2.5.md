# Aropyt v0.2.5 — Two Ways of Not Opening the Right Thing

Two fixes, both about double-clicking a document: on macOS the document never
arrived at all; in the Microsoft Store build it arrived, but wearing the app's
own icon.

## macOS opened an empty window

macOS does not pass the file path in the process arguments. Finder hands the
application an Apple Event (`kAEOpenDocuments`), which Tauri surfaces as
`RunEvent::Opened`. Aropyt only read `argv`, so the window came up with nothing
in it — no error, no document.

`src-tauri/src/lib.rs` now runs the event loop with a callback
(`Builder::build()` + `App::run`) instead of the shorthand, which installs an
empty one. `RunEvent::Opened` turns each `file://` URL into a local path, and
the paths go into the same pending queue the Windows command line has been
filling all along.

The queue is the part that matters. On a cold launch the event can arrive
before the webview has loaded, and an event emitted into a page with no
listener is simply lost. The frontend subscribes first and then drains the
queue, so it does not matter which happens first. An already-running instance
goes through the same path, and the window is brought to the front.

Only `file` URLs with a supported extension are accepted; anything else is
ignored rather than read as a file.

To check it, double-click a `.md` file in Finder twice: once with Aropyt closed,
once with it already running. Both should open the document in a tab. The
association only exists in the packaged `.app` — `tauri dev` does not register
it.

## The Store build gave every file the app icon

Explorer takes the icon of an associated file from the `<uap:Logo>` of that
association in the package manifest. All three associations in the MSIX package
pointed at `Square44x44Logo.png` — the app icon — so `.md`, `.tex` and
`.fountain` files were indistinguishable from Aropyt itself. The NSIS installer
already had per-type icons through `installer-hooks.nsi`; the Store package did
not.

Each association now names its own image (`Assets\markdown.png`,
`Assets\latex.png`, `Assets\fountain.png`), generated at pack time from the
256px renders of `icon/mdFile.svg`, `icon/texFile.svg` and
`icon/fountainFile.svg`. The pack script emits a 44px baseline plus
125/150/200/400 scale variants, so a high-DPI display does not have to upscale
a 44px bitmap. `npm run build:icons:files` regenerates the 256px sources when
the SVGs change.

After installing the new package, look at a `.md` file. If Explorer still shows
the old icon it is the shell icon cache: `ie4uinit.exe -show` or restarting
Explorer clears it.
