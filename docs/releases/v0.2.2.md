# Aropyt v0.2.2 — The Typora Kernel

The editor now runs on the upstream `aropyt-tauri` rendering and editing core.
That is the short version of this release; everything below follows from it.

## Headings behave like Typora

Put the caret on a title and the `#` never appears. The old renderer treated
headings as replaceable blocks, so a caret on a title exposed the marker and a
grey source backdrop. The upstream core treats headings as inline — only the
marker is hidden, the line keeps its heading class — so the document reads the
same whether or not the caret is in the title.

## Tables stay tables while you edit them

Previously a table rendered as a real `<table>` only while the caret was
outside it. Entering the table dropped the whole thing back to source: a
sixteen-row table filled the screen with pipes, and you edited it by counting
pipes.

The upstream core projects each cell while keeping the Markdown source in text
nodes, so DOM ranges and source offsets stay aligned. The table stays a table
while you type in it, and row/column insert and delete controls come along.

This replaced `wysiwyg/inline-render.ts` (115 KB). The upstream core is
21 files under `packages/core/src/editor-upstream/`, wired into `EditorAdapter`
through two injection points — `setBlockRenderer` decides where blocks begin
and end, `setSingleBlockRenderer` decides what each block renders to. Vim,
search, themes, word count and source-mode switching are untouched.

## Formulas: LaTeX delimiters now work

`\( … \)` and `\[ … \]` are equivalent to `$…$` and `$$…$$`. They are the
delimiters LaTeX itself uses, so pasting a formula from a paper or a notebook
usually produces them.

Both block rendering and inline decorations had to learn them; fixing only one
leaves inline formulas as source near the caret. Everything KaTeX supports
comes along:

```
vmatrix   cases   pmatrix   \left( … \right)
\tag      \operatorname   \lVert   \mathbb
```

Formulas render inside a **Shadow DOM** per instance. The upstream stylesheet,
the theme, and CodeMirror's dynamic line-wrapping all leak into `.katex` and
break its internal layout — integrals and fractions scatter into a column.
Per-property fixes and raising `katex.min.css` specificity both failed; a shadow
boundary is the only isolation that holds.

## GitHub alerts: English labels, real icons

Labels are always `Note` / `Tip` / `Important` / `Warning` / `Caution`. They map
one to one onto `> [!NOTE]` in the source; translating them breaks that link.

The icons are Octicon SVGs, replacing the emoji characters the upstream
stylesheet shipped. They are drawn with a CSS mask plus `currentColor`, so they
follow the type colour, and all three class families share one definition.

## Fixes

**Deleting a file did nothing.** The confirmation called `showMessage` without
`actions` — that is a toast, not a dialog. It has no buttons, disappears after a
few seconds, and resolves to `undefined` immediately, so the guard returned
before the delete. It now passes a Delete action and proceeds only when that
label comes back.

**A 10px gap between the header and the toolbar.** The upstream stylesheet has
an element selector `header { height: var(--titlebar-height) }`, meant for a
custom Electron title bar. Our header is also a `<header>`, so it was pinned to
30px inside a 40px grid row.

**Six heading levels, six colours.** The highlight style gave each level its own
colour. That is a code-editor convention for nesting; in a document it means a
screenful of headings in six colours while the levels still have to be
remembered. They use the body colour now, with size doing the work.

**Bold text had a second outline.** The Chinese font on this system has no
usable Bold face, so `font-weight: 700` found nothing. Two compensations were
tried and both left marks: `-webkit-text-stroke` is offset down-right on
WebView2, and `text-shadow` at 0.35px with zero blur rounds to a whole pixel,
giving every glyph a solid copy above and below. Both draw the glyph again
slightly offset, and with the same colour that always reads as two layers. Only
`font-weight: 700` remains.

## Development builds are distinguishable now

`npm run tauri dev` opens a window titled `Aropyt · DEV`, and its exe carries a
monochrome icon while the release build is green. `build.rs` picks
`window_icon_path` by profile — that is the only moment the taskbar and Alt+Tab
icon can be chosen; `set_icon` at runtime only changes the small one in the
title bar. `identifier` is untouched, since it decides where settings and drafts
live.

## Known limitations

**Bold weight depends on the system font.** With a Chinese font that has no Bold
face, `700` renders as regular. Bundling a font with real weights would fix it
and also remove the ClearType colour fringing that the shadow workaround made
more visible — that is a future release, not this one.

**The static asset directory grew to 10.5 MB.** The upstream stylesheet
directory, the mermaid UMD bundle and the KaTeX fonts are served from
`apps/web/public/`. Two UMD bundles (4 MB) were dropped when mermaid moved to
the project's own v12 through a dynamic `import()`.

## Upgrading

Nothing to do. Settings, drafts and workspaces are read from the same
`dev.aropyt.desktop` identifier, and the file tree gains nothing that changes
on-disk layout.
