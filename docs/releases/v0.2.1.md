# Aropyt v0.2.1 — Smaller Frictions

Nine fixes and additions that each remove a small annoyance. No new subsystems.

## The file tree can delete and rename

Right-click any row.

**Delete** asks first, because `fs::remove_file` does not reach the recycle
bin — there is no undo. Directories are removed only when empty: a recursive
delete of a whole subtree is not something a right-click should be able to do
by accident, so a non-empty directory surfaces the system's own error instead
of taking the children with it.

**Rename** happens where the name is: the row turns into an input with the
base name selected and the extension left alone, since that is almost never
what changes. Enter commits, Escape cancels, and clicking away commits too —
losing the edit because you clicked elsewhere is worse than committing a typo
you can fix.

It renames on disk directly rather than reading, writing and deleting: that
approach loses the modification time and can leave the file under neither name
if it fails halfway. The new name may not contain a path separator — moving is
a different action.

## Six heading levels, one button

H4–H6 did not exist. Adding them as three more buttons would have made the
heading group 160 px wide — half the toolbar for something used occasionally.

All six levels now share a single button: **scroll over it to change the
level**, click to apply. The icon and tooltip follow the selection, and the
tooltip says so, because nothing on screen advertises a wheel gesture.

## The formatting buttons can be hidden

Right-click the toolbar and uncheck "Show formatting buttons". Only the file
actions remain — open folder, open file, save, export. The choice is
remembered in `settings.jsonc`.

## Two ways dialogs were misbehaving

**They closed when you dragged out of them.** Clicking outside a dialog should
close it; dragging out should not. The backdrop used to close on any `click`
whose target was the overlay, which included selecting text inside the dialog
and releasing past its edge, and pressing inside then sliding out. Both read
as accidental closes. `mousedown` and `click` must now both land on the
overlay.

**A stale recovery banner could overwrite a different file.** The "this
document has unsaved changes from last time" banner is a floating notification,
so it stays on screen after you open something else. Its "use disk version"
action wrote into whatever the editor currently showed — open B while A's
banner is up, click it, and B's buffer holds A's content. The display looked
wrong but harmless; one save wrote A's text into B's file. The action now
re-opens its own file first.

## History gained a neighbour comparison

Each entry has a "vs. previous" button beside "vs. current". The old one
answers "what changed since I last saved", which is not the question you have
when scrolling back through history — the further back you look, the noisier
that diff becomes, because it spans everything since. Comparing two adjacent
snapshots answers "what did this version change".

## Search

**`Ctrl+Alt+F` toggles.** Pressing it again closes the workspace search. It is
not `Ctrl+Shift+F`: CodeMirror's own find variant also listens there, and both
panels opened at once in testing.

**The search box looks like the `Ctrl+F` bar** — same padding, same 13px type,
same background, and the focus border uses the same `--md-link` colour, which
resolves to `#5dcaa5` on dark and `#4aa63d` on light. A hard-coded green was one
colour for both themes and visibly brighter than the find bar next to it.

**A match count replaced "Select all".** That button only walked the *current
selection*, so with a cursor it matched at most one place — "select all"
behaved like "select here". Selecting hundreds of disjoint ranges is not a
workflow this editor has, so the button is gone and a count is there instead.
Documents over 200 KB skip the count: a per-keystroke full scan at that size
costs more than the number is worth.

## Under the hood

`engine.ts` and `runner.ts` moved from `apps/web` into `packages/core`. They
are transport-agnostic — the decision table and the executor know nothing about
how bytes move — and both the open-source build and any future edition need
them. `dav.ts` and `host.ts` stay put: WebDAV is an open-source feature, not a
core capability.

The save icon was replaced.

## Upgrading

Nothing to migrate. One note: the file tree's delete and rename need an open
workspace, so they will not appear when a single file is opened directly.

- **The recovery-banner fix** — reproducing it needs two files, a draft on one,

## Deferred

**Table editing.** The current behaviour — a table renders as a real `<table>`
until the cursor enters it, then falls back to source — is by design: the
rendered form is a non-editable widget. For a table taller than the viewport
that fallback is unpleasant, and several attempts to improve it were reverted
because they fought the existing design rather than replaced it.

A working approach exists in the upstream implementation (kept in this
repository for reference): project each cell to DOM while keeping the Markdown
source in text nodes, so DOM ranges and source offsets stay aligned. That is
about 1600 lines. Scheduled for v0.2.2.
